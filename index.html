Get started

Confluence

  1. Attach your .yaml, .yml or .json OpenAPI file to the page.
  2. Type /OpenAPI Viewer in the editor, choose the attachment (or paste a spec up to 32 KB) and save.
  3. Optional: choose how operations expand and whether to show the description, servers and schemas.

Upload a new version of the same attachment and the macro shows the latest one automatically.

Jira

  1. Attach the spec file to an issue.
  2. Open the OpenAPI spec panel from the issue's apps menu. With several spec files attached, pick one from the dropdown.

Change report

Use Compare with… above the docs:

  • Confluence: compare with any earlier version of the attachment.
  • Jira: compare with another spec file on the same issue (for example api-v1.yaml and api-v2.yaml).

The report groups changes as Breaking (removed endpoints or responses, new required parameters or fields, type changes, removed request enum values, new response enum values, security changes), Added (new endpoints) and Changed (everything else). Copy report copies it as text for a Jira comment or release notes.

FAQ

Why no "Try it out"? It would send requests from Confluence to your API servers, which means data leaving Atlassian and CORS errors. Use cURL on any operation instead: it copies a ready-to-run command with parameters, auth header and an example body.

Can it load specs from a URL or GitHub? No, by design: that would require external network access. Attach the file instead.

Split specs with $ref to other files? Supported. Attach the referenced files next to the spec (same page or issue); they are matched by file name, so ./schemas/pet.yaml finds pet.yaml. References to URLs are not fetched. Missing files are listed above the docs.

PDF and Word export? The macro exports as a table of endpoints with the API title and description.

Who can see the spec? Exactly the people who can see the page or issue and its attachments. The app uses each viewer's own permissions.

Privacy policy

Last updated: 4 October 2026.

OpenAPI Viewer runs entirely on Atlassian Forge and qualifies as Runs on Atlassian. It has no external servers. It reads only the attachment or pasted text you choose, using your Atlassian permissions, to display it in your browser or to build the PDF/Word export. It stores nothing beyond the macro settings that Confluence saves in the page. It sends no data to the developer or to any third party, and uses no cookies, tracking or analytics. Atlassian's own privacy policy covers the Atlassian platform.
